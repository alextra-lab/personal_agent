# Nemotron 3.5 Bolt as the local primary — desk check against Flash-Next

**Date:** 2026-10-20 · **Seat:** adr (Opus 5.5) · **Ticket:** FRE-1626 (step 1 of 2) · **Status:** verdict for the owner

## Verdict: no-go for step 2 at this date

Three facts decide it:

1. **The model does not run on Metal today.** llama.cpp crashes on the first prompt with this model, on every quant. The cause is a missing Metal kernel for 9 experts per token (issue [#30610][i30610], open). The one-line fix ([PR #30699][p30699]) is approved but not merged. The production build b11689 does not contain it.
2. **The published quality is far below Flash-Next.** Artificial Analysis rates Flash-Next 40 and Bolt 21 on its Intelligence Index. Flash-Next leads on all ten evaluations on that page, and the agentic ones show the largest gaps: AutomationBench 56% against 15%, Terminal-Bench 25% against 0% ([AA comparison][aa-cmp]). The ticket requires a faster turn "without a loss of quality".
3. **The latency gain is an estimate of 16% to 41% per turn, not a certainty.** Bolt's decode is about 1.3 to 1.5 times faster, by estimate. Its prefill gain is between none and 2.1 times, by estimate. Both figures come from other machines or another engine (§8).

The owner's claim "better than the gemma-4" has a source: NVIDIA's own benchmark table, and Artificial Analysis (21 against an estimated 17). But Gemma is not the baseline. Gemma 4 26B-A4B already lost to Flash-Next on answer quality in the FRE-1517 sessions.

**Re-entry conditions.** Reopen step 2 when both hold:

- A llama.cpp release contains the `<9>` kernel fix (PR #30699 or a successor).
- The owner accepts the quality evidence below as a risk worth a measurement. The alternative is an independent agentic benchmark that puts Bolt near Flash-Next.

§10 gives the step 2 plan for that case.

## What this work did and did not do

- **No model calls.** No call to :8600 or any inference endpoint, no paid inference and no gateway turn.
- **No download** to the production Mac. The research read GGUF headers over HTTP range requests and downloaded no weights.
- **No change** to `config/`, `.env` or any deployment. This PR adds this file only.
- One read-only Elasticsearch query (`agent-logs-2026-10*`, `model_call_completed`) gives the Flash-Next turn shape in §8.
- The slm_server facts (memory, loaded model, disk, llama.cpp ancestry) come from master's relay on FRE-1626, 2026-10-20. This seat did not contact slm_server.
- A research subagent read the web sources. This seat checked the three deciding facts again on GitHub and Artificial Analysis: the open issue, the unmerged fix with its diff, the first release, and the Intelligence Index scores.

All sources were read on 2026-10-20.

**Prompt cache on a hybrid model.** llama.cpp cannot roll back a recurrent state. It continues from the slot's live end state, or restores a context checkpoint (`--ctx-checkpoints`, default 32 per slot; `--checkpoint-min-step`, default 8192). This is the same mechanism as for Flash-Next ([server README][srv-readme]; PR #16382 extended it to hybrid models).

The Bolt template drops the thinking of every assistant message before the last `user` message (`truncate_history_thinking`, default true). Tool results do not count as a `user` message for this rule ([template][hf-tmpl], `last_user_idx`). So:

- Inside one tool loop, the prefix stays stable, and each call continues from the live end state.
- At a new user turn, the prompt changes at the previous turn's first assistant message. The server restores the checkpoint at the last user message and re-processes the rest.

Qwen templates drop earlier thinking in the same way, so this is not a new cost against Flash-Next. (Reading of the template text. Not measured.)

## 3. Fit on the M4 Max

Bolt replaces Flash-Next. It does not run beside it. Owner clarification on FRE-1626, 2026-10-20: "It would be a replacement to qwen3.8 flash".

- **Beside Flash-Next: no.** Flash-Next holds 83.6 GiB RSS. The smallest Bolt quant (UD-IQ1_S, 17.24 GiB) brings the total to about 101 GiB. The GPU limit is about 96 GiB by the common 75% default, which is not verified on this Mac (slm_server relay).
- **Alone: yes, with room.** Estimate for UD-Q4_K_XL at `--ctx-size 131072 --parallel 3`, computed from [config.json][hf-cfg]:

| Item | Size |
|---|---|
| Weights | 46.77 GiB |
| KV cache, q8_0, 8 attention layers × 2 KV heads × 128 dims, 131,072 tokens | 0.53 GiB |
| Recurrent state, f32, 40 Mamba layers: about 165 MiB per sequence × 3 slots | 0.48 GiB |
| Context checkpoints, about 165 MiB each, up to 32 per slot × 3 slots (inference: a checkpoint holds the recurrent state) | up to 15.5 GiB |
| Vision projector | 1.61 GiB |
| **Total, upper bound** | **about 65 GiB** |

NVIDIA's own table gives 23.83 GB for the 22 GB file at 128K, one sequence, without vision ([tech report][nv-tr] Table 2). That agrees with the KV and state figures above.

The attention KV cache is very small, because only 8 of 88 layers are attention layers. Flash-Next needs 83.6 GiB, so a swap to Bolt frees about 18 GiB or more.

**Disk:** 727 GiB free on the models drive (slm_server relay). One quant needs 22 to 79 GB.

**Dialect (ADR-0145).** The existing `llamacpp_qwen` dialect carries Bolt without change. ## 5. Reasoning control

Source for every row: [template][hf-tmpl] and the [GGUF card][hf-gguf].

| Control | Values | Default | Effect |
|---|---|---|---|
| `enable_thinking` (chat-template kwarg) | true, false | true | false makes the generation prompt `<think></think>`. Thinking is fully off. |
| `medium_effort` | true, false | false | true adds `{reasoning effort: efficient}` to the last user message |
| `truncate_history_thinking` | true, false | true | Drops thinking before the last user message (§2) |

There is no `/think` or `/no_think` text switch. Thinking and the answer share `max_tokens`. llama.cpp also has `--reasoning-budget N` ([server README][srv-readme]).

So Bolt can carry all four modes that Flash-Next serves: `default` (on), `worker`, `planner` and `fast` (off). Sampling values for those modes are the owner's step 2 decision. NVIDIA's recipe gives `--temp 1.0 --top-p 0.95` ([GGUF card][hf-gguf]).

## 8. Expected effect on turn time (an estimate)

**The turn shape.** Flash-Next calls in production, October 2026, from `agent-logs-2026-10*` (`model_call_completed`, `model: unsloth/qwen3.8-flash-next`). 829 calls: 304 `primary`, 525 `sub_agent`, over 100 primary turns. ES can drop events, so these counts are provisional. "Uncached" is `input_tokens − cache_read_tokens`, summed over a turn's primary calls.

| Primary turn | Calls | Uncached prompt tokens | Output tokens |
|---|---|---|---|
| Median | 2 | 14,409 | 1,900 |
| p90 | 7 | 27,215 | 5,762 |

**Bolt's speed on this Mac, estimated for UD-Q4_K_XL on llama.cpp:**

- *Decode, 28 to 32 t/s.*
  - Low end: the M3 Ultra Q4_K_M figure (41.61) × the bandwidth ratio. The M4 Max has 546 GB/s ([Apple][apple-m4]); 128 GB is offered only on that chip. The M3 Ultra has 819 GB/s ([Apple][apple-m3]). 41.61 × 546 / 819 = 27.7.
  - High end: Gemma on this Mac decodes 47.6 t/s and reads about 4.1 GB of weights per token (4B active at 8.3 bits). That gives about 197 GB/s effective. Bolt UD-Q4_K_XL reads about 6.1 GB per token (9B active at 5.4 bits): 197 / 6.1 = 32.2.
- *Prefill, 290 to 600 t/s.*
  - Low end: the M3 Ultra pp2048 (584) × 40 / 80 GPU cores. The user's core count is not stated, so the true value can be higher.
  - High end: the MLX figure on an M4 Max (571 to 620). That is a different engine and a 2-bit quant.
  - A cross-check points to the low end. Gemma (4B active) prefills 997 t/s on this Mac's cold 3.9k cell. Scaled by 4 / 9 active, that gives about 443, which equals Flash-Next's 449 on the same cell.

**Turn time at equal output tokens** (Flash-Next at the llama-bench rates of 285 and 21.1 t/s; MTP excluded on both sides):

| Turn | Flash-Next | Bolt, low case (290 / 28) | Bolt, high case (600 / 32) |
|---|---|---|---|
| Median | 50.6 + 90.0 = **141 s** | 49.7 + 67.9 = **118 s** (−16%) | 24.0 + 59.4 = **83 s** (−41%) |
| p90 | 95.5 + 273.1 = **369 s** | 93.8 + 205.8 = **300 s** (−19%) | 45.4 + 180.1 = **225 s** (−39%) |

Limits of this estimate:

- **Production Flash-Next runs MTP** (median 26 t/s, `config/models.yaml:230`). At 26 t/s its median turn is about 124 s, so Bolt's estimated gain falls to 5% to 33%.
- **Bolt has no MTP.** Its drafter is not tested on Metal.
- **Output length decides it.** In the low case, Bolt loses its gain if it writes more than 1.34 times Flash-Next's output tokens. In the high case, the limit is 1.96 times. AA's totals (230M against 240M) suggest similar verbosity, but on other tasks.
- Fast mode (thinking off) changes the output length for both models in the same direction.

## 10. Step 2 plan, for when the re-entry conditions hold

This follows the Gemma path on FRE-1517 (stage-1 screen, then scripted sessions, then the D7 probe). Each stage has a stop rule.

**Configuration.**
- Quant: unsloth **UD-Q4_K_XL** (50.22 GB). It has no NVFP4 tensors, so nothing falls back to the CPU. Do not use NVIDIA's 24GB file or unsloth's non-UD `IQ2_XXS`.
- Engine: the first llama.cpp release that contains PR #30699, or a later one. Production flags: `--ctx-size 131072 --kv-unified --parallel 3`, KV q8_0, `--jinja`, the `mmproj`. No MTP exists. The LiLiCorr drafter is a separate optional arm, only if Metal support is confirmed first.
- Catalog: master adds a study deployment (dialect `llamacpp_qwen`), with `default`, `worker` and `fast` modes, and a study-only `planner` mode. No role binding points at it. A session selects it through `/chat`'s `model` parameter, as for Gemma.

**Stage 1 — slm_server screen, Bolt alone, about 1 hour.** The Gemma screen of 2026-10-10 took 46 minutes.
- llama-bench pp16384 and tg256, against Flash-Next's 285 and 21.1.
- The server cells of 2026-10-10.
- The four-check tool smoke: one call, two parallel calls, `tool_choice: "none"` after a tool result, and thinking off with tools and a system prompt.
- Memory at `--ctx-size 131072`.
- *Stop rule, to pre-register:* stop if any smoke check fails. Also stop if the measured rates, applied to the median turn above, do not give at least 20% less time than Flash-Next with MTP (124 s).

**Stage 2 — the FRE-1517 scripted sessions.**
- The three scripts of about 20 turns each run on the isolated eval gateway (:9003), Bolt alone.
- The owner scores blind, against Flash-Next's existing FRE-1517 runs on the same scripts.
- Search memory is off, or the graph is restored for each arm. Sequential arms contaminate each other through entity extraction.
- Per arm: turn wall clock p50 and p90, output tokens per turn (the verbosity check of §8), malformed tool calls, and the worker report fields.
- At the stage-4 rate of 17 turns in about 70 minutes, 60 turns take about 4 hours.

**Stage 3 — the ADR-0154 D7 probe** (`scripts/eval/fre1537`), with the paired delay arm, before Bolt's `planner` mode can reach D2. About 10 minutes for the Gemma run of 2026-10-10.

**What the owner must approve:**
1. Lift the FRE-1573 model-testing hold for this test.
2. A swap window: Flash-Next stopped, and the owner's chats on a cloud primary.
3. The download of about 50 GB to the models drive.
4. The catalog PR and its gateway rebuild.
5. The pre-registered stop rules and scripts.
