# FRE-990 — Captain's Log reflection enable flag

Ticket: FRE-990. Related: FRE-710 (cadence gate), ADR-0124, cost incident report 2026-07-25.

## Problem

No setting turns Captain's Log reflection off. The cadence flag `captains_log_reflection_cadence_enabled`
looks like an off switch, but `False` makes `not settings.captains_log_reflection_cadence_enabled`
true, so reflection fires on every turn. Master used a 1000-day debounce interval as a stand-in.
That interval does not stop the iteration-limit bypass or the eval-mode bypass.

## Design

- New setting `captains_log_reflection_enabled: bool = True` in `config/settings.py`, next to the
  cadence settings.
- In `orchestrator/executor.py` (reflection call site, near line 4839), make the new flag the
  outermost gate: `should_reflect = enabled and (eval_mode or not cadence_enabled or gate...)`.
  The `and` short-circuits, so the cadence gate is not consulted and its state does not change
  when reflection is disabled.
- A disabled skip logs a new event `captains_log_reflection_skipped_disabled`. The existing event
  `captains_log_reflection_skipped_cadence` keeps its meaning.
- Correct the comment beside the expression. The "kill switch" wording is wrong: the cadence flag
  set to `False` means "reflect on every turn".
- Correct the cadence flag description to say the same.
- **No rename** of the cadence flag. A rename changes the env var
  `AGENT_CAPTAINS_LOG_REFLECTION_CADENCE_ENABLED`. An old value set in a deployed `.env` would be
  ignored without an error. The ticket also says to leave the cadence flag exactly as it is.
  The comment and description fix removes the trap. The negative test pins the inversion.
- Forward the flag to both eval gateways in `docker-compose.eval.yml` as
  `${AGENT_CAPTAINS_LOG_REFLECTION_ENABLED:-true}` (Codex plan review). The `:-true` default is needed
  because an empty value fails the bool parse. Add the key to `_BEHAVIOUR_KEYS` in
  `tests/personal_agent/config/test_docker_compose_eval_yaml.py`, and let that test accept `${KEY:-default}`.
- Add `AGENT_CAPTAINS_LOG_REFLECTION_ENABLED` to `.env.example` and a row to
  `docs/reference/CONFIG_INVENTORY.md` (generated by `scripts/audit/config_inventory.py`).

`_trigger_captains_log_reflection` is the only caller of `generate_reflection_entry`, so the gate at
the call site closes every Captain's Log reflection model call. Failure-path reflection has its own
flag and is out of scope.

## Tests (`tests/test_orchestrator/test_reflection_cadence_gate.py`)

Run: `make test-file FILE=tests/test_orchestrator/test_reflection_cadence_gate.py`

1. Default: `settings.captains_log_reflection_enabled is True`.
2. Enabled false + turn over the iteration limit → `generate_reflection_entry` not called. The
   real trigger runs, with `generate_reflection_entry` and `CaptainLogManager` mocked (Codex plan
   review: mocking the trigger made the model-call assertion vacuous). A control test with the flag
   true proves the counter sees one call.
3. Enabled false + `eval_mode=True` → no reflection.
4. Enabled false + cadence flag false → no reflection (outermost gate).
5. Enabled true + `eval_mode=True`, second turn inside the interval → reflects (eval bypass pinned).
6. Existing tests stay unchanged and pass (enabled true + cadence true is byte-identical).
7. Existing cadence-false test: docstring updated to state the inversion (reflect every turn).

Write tests 2–5 first and confirm they fail (the setting does not exist).

## Acceptance criteria

- AC-1: flag false + iteration-limit turn → no reflection, no `generate_reflection_entry` call.
- AC-2: flag true + cadence true → existing cadence tests pass unchanged.
- AC-3: eval-mode bypass tested with the flag true. Flag false beats eval mode.
- AC-4: cadence flag false (flag true) still reflects every turn, pinned by a test.
- AC-5: the misleading comment is corrected.
