## Measured before this plan

- Pins found by `grep -rnE '3\.12|py312|cp312'`, listed in Step 2.
- `ruff@0.17.3 format --check --config 'target-version="py314"' src/`: 42 files reformat. Every changed
  line is `except (A, B):` to `except A, B:` (PEP 758). 73 removed `except (` lines. `ruff check` with
  py314 passes with 0 findings.
- Repo scan, `get_event_loop()` outside an `async def`: one hit, `brainstem/mode_manager.py:301`.
  The other 18 call sites are inside coroutines, where the call returns the running loop on 3.14.
- No use in `src`, `scripts` or `tests` of: PEP 594 removed modules, `asyncio` policy API,
  `asyncio.iscoroutinefunction`, `multiprocessing`, `ProcessPoolExecutor`, `ssl`, `ast.Str`/`ast.Num`,
  `pkgutil.find_loader`, `locale.resetlocale`, `logging.warn`, `unittest.makeSuite`.
- `__annotations__` is read only in tests, by `getattr(GenerateReflection, "__annotations__", {})`.
- Dependencies at the locked versions: `dspy` 3.4.1 and `elasticsearch` DSL read
  `annotationlib` on 3.14. `litellm/_logging.py:857` is in a `try/except Exception`. `litellm/_service_logger.py:118`
  catches `RuntimeError`. `dspy/utils/syncify.py:21` is reached only with a running loop.
- `code_regions.py` `_PROSE_TOKEN_TYPES` holds `COMMENT`, `STRING` and `FSTRING_MIDDLE`.
  On 3.14 `print(t"Paris has 9 million residents")` parses and tokenizes as `TSTRING_*`. On 3.12 the same
  text is a `SyntaxError`, so it never earned the proven-code exemption. On 3.14 it does, and its content is
  not extracted. This is the same bypass that the `FSTRING_MIDDLE` docstring describes.
- `/opt/seshat/.venv/bin/python` runs `seshat-dispatch-orchestrator.service` and `seshat-gating-watcher.service`.
  When master runs `uv sync --extra dev`, uv replaces that environment under both running processes.
- System `python3` on the VPS is 3.13.5. The `.claude/hooks` that use it parse JSON from stdin only.
  They do not parse `src/`, so `except A, B:` (3.14 only syntax) does not affect them. CI has no step that
  runs a system Python on `src/`.

## Step 4. Code fixes, test first

a. `grounding/code_regions.py`: add `tokenize.TSTRING_MIDDLE` to `_PROSE_TOKEN_TYPES`, and extend the docstring.
   Test in `tests/personal_agent/grounding/test_code_regions.py`: t-string content is in `CLASSIFY`, with
   the same shape as `test_fstring_content_is_extracted_like_any_other_literal`.

b. `brainstem/mode_manager.py:301`: on 3.14 `asyncio.get_event_loop()` raises `RuntimeError` with no current
   loop, and the raise leaves `transition_to` after the mode already changed. On 3.12 the fallback created a
   task on a loop that never ran, so the event was already dropped. Fix: with no running loop, do not create
   the coroutine, and log `mode_transition_bus_publish_skipped` with `trace_id`. The mode change stands.
   Test in `tests/test_brainstem/test_mode_manager.py`: a sync call with a bus and no loop does not raise, the mode
   changes, the bus is not called, and no "never awaited" warning appears.

c. Any failure that the suite shows on 3.14. Fix the cause. If the cause is in a dependency, list it.
