# FRE-1683 — the development-agent broker (ADR-0159 T2)

Implements ADR-0159 D4.3, D4.4 and D5. Tier-1. Diff class: escalated (cost code, schema, security boundary).

## Scope

- A new service `seshat-dev-broker`, from `Dockerfile.gateway`, on `cloud-sim` and `dev-agent`.
- A model route on the broker's `dev-agent` address: OpenAI-compatible `POST /v1/chat/completions`, with `stream` support.
- A control relay on the broker's `cloud-sim` address: authenticated by a secret, forwards only to the current job's OpenCode server.
- Three ledger tables, the job token table, a restricted role `seshat_dev_broker`, and the cost-gate role `dev_agent`.

## Facts that shape the design (read on `main` 91d90806)

1. `LiteLLMClient.respond()` (cloud) reserves on the cost gate itself, under `budget_role`. So the broker reserves its job and month counters first, then calls `respond()` with `budget_role="dev_agent"`. Order matches ticket item 4.
2. The cloud branch of `respond()` does not stream. The broker calls it without streaming and sends the finished answer as SSE chunks when the request asks for `stream`. One dispatch path stays (ADR-0141 D1).
3. On `asyncio.CancelledError`, `respond()` commits its estimate on the cost gate (FRE-1733). So `asyncio.wait_for(respond(...), 150)` settles the cost-gate reservation at its estimate, inside the 180 s TTL. The broker passes no `timeout_s`, so a litellm timeout cannot fire first and refund.
4. FRE-1690 already stores `counter_ids` on each reservation, so a call across a window boundary settles the right cost-gate counters. The hold before a boundary (ticket item 6) stays, as the ADR and the ticket require. It is now defense in depth.
5. FRE-1680 added the `scaleway` provider, `glm-5.3-scaleway` and `deepseek-v4.1-flash-scaleway`. The `scaleway` provider is on the OpenAI-SDK guard route.
6. No record holds a Scaleway price for `qwen3.8-27b` (FRE-1679 and FRE-1680 read in full; the Scaleway pages refuse automated reads). The owner kept Qwen on OVH as cheaper (FRE-1680, 2026-10-24). **This PR adds no Qwen entry.** A wrong price breaks the cap. The handoff asks for the console price.
7. `CostGate.connect()` reads stored cap overrides from `settings_overrides` (FRE-1723). ADR D4.4 limits the broker role to the cost-gate, token, spend and `api_costs` tables, so the role gets **no** grant on it. The broker's cost gate enforces the file caps. A cap that the owner lowers in the PWA does not reach the broker. The broker's own job and month caps still bound its spend. The handoff names this.
8. Adding `dev_agent` to `role_map.py` makes the gateway refuse to start until the real, gitignored `budget.yaml` declares the role. Deploy runbook item.

## Schema (`0038_dev_broker.sql`, mirrored in `init.sql`)

```sql
CREATE TABLE IF NOT EXISTS dev_job_tokens (
    token_hash  TEXT PRIMARY KEY,                -- sha256 hex of the raw token
    job_id      UUID NOT NULL UNIQUE,
    model_key   TEXT NOT NULL,                   -- catalog key, e.g. deepseek-v4.1-flash-scaleway
    trace_id    UUID NOT NULL,                   -- the job's trace (api_costs joins on it)
    session_id  UUID NOT NULL,
    status      TEXT NOT NULL CHECK (status IN ('active','stopped','revoked')),
    stop_reason TEXT CHECK (stop_reason IN ('cap_reached','cost_unknown')),
    expires_at  TIMESTAMPTZ NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS dev_job_spend (
    job_id UUID PRIMARY KEY, committed_usd NUMERIC(12,6) NOT NULL DEFAULT 0,
    reserved_usd NUMERIC(12,6) NOT NULL DEFAULT 0, updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW());
CREATE TABLE IF NOT EXISTS dev_month_spend (
    month_start DATE PRIMARY KEY, committed_usd NUMERIC(12,6) NOT NULL DEFAULT 0,
    reserved_usd NUMERIC(12,6) NOT NULL DEFAULT 0, updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW());
CREATE TABLE IF NOT EXISTS dev_job_calls (
    call_id UUID PRIMARY KEY, job_id UUID NOT NULL, model_key TEXT NOT NULL,
    month_start DATE NOT NULL, prompt_token_bound INT NOT NULL, max_output_tokens INT NOT NULL,
    input_tokens INT, output_tokens INT,
    reserved_usd NUMERIC(12,6) NOT NULL, settled_usd NUMERIC(12,6),
    status TEXT NOT NULL CHECK (status IN
        ('reserved','settled','cost_unknown','timed_out','cancelled','failed','gate_denied')),
    created_at TIMESTAMPTZ NOT NULL, settled_at TIMESTAMPTZ);
```

Role `seshat_dev_broker` (dev password, `ALTER ROLE … PASSWORD` at deploy, same as `seshat_app`):

- `dev_job_tokens`: `SELECT`, and `UPDATE (status, stop_reason, updated_at)` only. No `INSERT`: only the gateway issues tokens.
- `dev_job_spend`, `dev_month_spend`, `dev_job_calls`: `SELECT, INSERT, UPDATE`.
- `budget_counters`, `budget_reservations`: `SELECT, INSERT, UPDATE`, plus `USAGE` on their sequences.
- `api_costs`: `INSERT` and `SELECT (id)` only (the insert uses `RETURNING id`), plus `USAGE` on its sequence.
- No `ALTER DEFAULT PRIVILEGES`. So `dev_jobs` (FRE-1684) gets no grant.

## The counter transactions (security-critical)

The clock is injected. Every time value in SQL is a parameter from `Clock.now()`, never `NOW()` in a check.

**reserve(token_hash, model_key, amount, prompt_token_bound, max_output_tokens, now)** — one transaction:

1. `SELECT … FROM dev_job_tokens WHERE token_hash=$1 FOR UPDATE`. Refuse (no write) if absent, not `active`, `expires_at <= now`, or `model_key` differs.
2. `INSERT … ON CONFLICT DO NOTHING` the job row and the month row (`month_start(now)`).
3. `SELECT committed_usd + reserved_usd … FOR UPDATE` on the job row, then on the month row. Lock order everywhere: token → job → month.
4. If `job_total + amount > job_cap` or `month_total + amount > month_cap`: `UPDATE dev_job_tokens SET status='stopped', stop_reason='cap_reached'`, commit, return `Refused(cap_reached)`.
5. Else add `amount` to `reserved_usd` on both rows and insert the `dev_job_calls` row (`status='reserved'`, `month_start` stored). Return `Admitted(call_id, job_id, trace_id, session_id)`.

**settle(call_id, outcome, now)** — one transaction. Outcome is one of `Settled(cost, input_tokens, output_tokens)`, `CostUnknown`, `TimedOut`, `Cancelled`, `Failed`, `GateDenied`:

1. `SELECT … FROM dev_job_calls WHERE call_id=$1 FOR UPDATE`. Require `status='reserved'` (idempotence: a second settle is a no-op).
2. Lock the token row, then the job row, then the call's stored month row.
3. `spent` = cost for `Settled`; = `reserved_usd` for `CostUnknown`, `TimedOut` and `Cancelled`; = 0 for `Failed` and `GateDenied`.
4. Both rows: `reserved_usd -= reserved`, `committed_usd += spent`.
5. `CostUnknown`: set the token `stopped`/`cost_unknown` if it is still `active`.
6. Update the call row (status, tokens, `settled_usd`, `settled_at`).

A `Settled` cost above the reservation is committed as reported, and the token is set `stopped`/`cost_unknown` in the same transaction: the worst case was wrong, so the job must stop. One call can overshoot at most once. Reserve never waits on an existing call row, so the settle order (call → token → job → month) cannot form a cycle with reserve.

## The model route, per request

1. Read the body with the byte limit. Bearer token → `sha256`. `check_token` (no lock): 401 unknown, 403 not active / expired / other model.
2. Clamp `max_tokens` (or `max_completion_tokens`) to `min(request, config clamp, catalog max_tokens)`.
3. Worst case = `bound × input price + clamp × output price`, from the catalog prices (USD), rounded up to 6 decimals. `bound` = UTF-8 byte length of the JSON of `messages` and `tools` + 1024. The three models use byte-level BPE tokenizers, where a token covers at least one byte, so `bound` is an upper bound on the prompt tokens. The JSON keys and quotes per message exceed the chat-template tokens. A model with no catalog price is refused (fail closed).
4. Hold: while `seconds_until_safe(clock.now(), 150) > 0`, `await clock.sleep(…)`.
5. `reserve`. Refused → 403 with `cap_reached` (or the token reason).
6. `wait_for(dispatcher.dispatch(…), call_timeout_seconds)` with the job's `TraceContext(trace_id=job trace hex, session_id=job session)`.
   - `TimeoutError` → settle `TimedOut`, 504.
   - `BudgetDenied` → settle `GateDenied`, 503.
   - other `Exception` → settle `Failed`, 502.
   - response without `prompt_tokens` and `completion_tokens`, or `cost_usd <= 0` → settle `CostUnknown`, return the answer.
   - else settle `Settled`, return the answer.
   - `asyncio.CancelledError` or any other `BaseException` after the reserve → settle `Cancelled` (worst case) under `asyncio.shield`, then re-raise. No path leaves a `reserved` row behind while the process lives.

`respond()` fix (codex finding 4). Today a cancellation in the inference-slot wait, or during `gate.commit`, leaves the cost-gate reservation `active` until the reaper expires it. That breaks D5.10. Change in `litellm_client.py`, cloud branch only:

- a `dispatched` flag set just before `litellm.acompletion` / `aresponses_as_chat`, and a `settled` flag set by every settle;
- a `except asyncio.CancelledError` on the outer slot `try`: if not `settled`, commit the estimate when `dispatched`, else refund; both under `asyncio.shield`; re-raise;
- `await asyncio.shield(gate.commit(...))` for the final commit.

Tests: cancel during the slot wait → reservation `refunded`; cancel during the final commit → reservation `committed`.
7. Answer → OpenAI `chat.completion` JSON, or SSE (`chat.completion.chunk`: role+content, tool-call deltas, finish chunk, usage chunk if `stream_options.include_usage`, `[DONE]`).

Forwarded request fields: `messages`, `tools`, `tool_choice`, `temperature`, `max_tokens`. Others are dropped.

## The control relay

- Header `X-Dev-Broker-Secret`, compared with `hmac.compare_digest`. A broker with no secret refuses to start.
- `/{method} /relay/{job_id}/{path}`. The job must have a token in `active` or `stopped`, not `revoked`, not expired. Else 404.
- Target host = `agent_container_name(job_id)`, resolved through Docker DNS. The address must be inside the broker's own `dev-agent` subnet. Else 502. The broker connects to the address, port = OpenCode port, with `httpx.URL(scheme, host, port, path)` so no path can change the host.
- Forward method, query, body, `Authorization`, `Content-Type`, `Accept`. Strip the secret header and hop-by-hop headers. No redirects. Stream the response (the OpenCode event stream is SSE).

## Listeners

At start, `psutil.net_if_addrs()` gives the IPv4 addresses. Exactly one must sit in `control_subnet` (`172.25.0.0/16`, the fixed `cloud-sim` subnet). Exactly one other non-loopback IPv4 must exist: the `dev-agent` address, with its netmask as the relay subnet. Otherwise the broker refuses to start. The model app binds `<dev-agent ip>:8700`. The control app binds `<cloud-sim ip>:8701`. Never `0.0.0.0`.

## Compose service

Startup (codex finding 1): load the model config, `register_model_pricing`, `load_budget_config` + `validate_role_totality`, `CostGate(...).connect()`, `set_default_gate`, cost tracker `connect`, then the ledger pool. Shutdown closes all three pools. No reaper: the gateway's reaper already sweeps the shared counters.

`seshat-dev-broker`: `build: Dockerfile.gateway`, no `env_file`, `user: "65534:65534"`, `read_only: true`, `cap_drop: [ALL]`, `no-new-privileges`, `tmpfs` `/tmp` and `/app/telemetry`, `mem_limit: 512m`, `pids_limit: 128`, no volumes, no socket, no ports. `environment:` exactly the three credentials of D4.4 and non-secret runtime values: `APP_ENV`, `AGENT_DATABASE_URL` (role `seshat_dev_broker`, `${DEV_BROKER_DB_PASSWORD:?}`), `AGENT_SCALEWAY_SECRET_KEY`, `AGENT_DEV_BROKER_CONTROL_SECRET`. Command `/app/.venv/bin/python -m personal_agent.dev_broker`. Health check `… -m personal_agent.dev_broker --health`. Networks `cloud-sim` and `dev-agent` (alias `dev-broker`).

## Deploy runbook (for master)

1. Add role `dev_agent` to the real `config/governance/budget.yaml` (roles + `uncapped_roles`), or the gateway refuses to start after the rebuild.
2. Apply `0038_dev_broker.sql` with `AGENT_DATABASE_ADMIN_URL`. Then `ALTER ROLE seshat_dev_broker PASSWORD '<DEV_BROKER_DB_PASSWORD>'`.
3. Add `DEV_BROKER_DB_PASSWORD` and `AGENT_DEV_BROKER_CONTROL_SECRET` to `/opt/seshat/.env`.
4. Rebuild `seshat-gateway`, then build and start `seshat-dev-broker`.
5. Run `uv run python scripts/verify_dev_broker.py` and expect every check `PASS`.

## Changes after self-review

- Every fallible step of the request (including `temperature`) runs before the reserve.
- A sweep settles calls `reserved` past the call limit + 60 s as `Cancelled`, at start and every 60 s.
- `LLMClientError` settles `Failed` (zero). Any other exception settles `CostUnknown` (worst case, token stopped).
- `respond()`: the inner commit and refund are shielded too.
- Relay: one guarded client per request, allowlist = the target address (ADR-0132 D2), closed in the stream's `finally`.
- `DomainGuard.note_staleness` is silent in allowlist mode (it never reads the feed).
- Compose: the three credentials default to empty (`${VAR:-}`), so a missing value cannot break another service's deploy. `net.ipv4.ip_forward: 0`.
- `finish_reason` is `tool_calls` whenever tool calls are present.
