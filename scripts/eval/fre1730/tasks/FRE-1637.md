# FRE-1637: PWA turn cost stays $0.00 for the whole turn and jumps to the total at the end

An owner turn on `gpt-6.1-sol` ran for about ten minutes. The `turn_status` STATE_DELTA events in `session_events`:

| seq | time | `turn_cost_usd` | `session_cost_usd` |
| -- | -- | -- | -- |
| 3 | 19:45:22 | 0.0 | 0.000009 |
| 4 | 19:45:22 | 0.0 | 0.000009 |
| 22 | 19:54:04 | 0.0 | 0.000009 |
| 26 | 19:55:09 | 0.0 | 0.000009 |
| 28 | 19:55:09 | 2.084922 | 2.084922 |

By 19:54:04, the trace had about $1.80 in `api_costs` (the planner and three helpers on Sol). The final value is correct: 2.084922 against a sum of 2.0849 over 38 `api_costs` rows.

## What to change

Find where `turn_cost_usd` is computed for the `turn_status` event, and make each emission carry the cost recorded so far for the trace, including the helpers. Optionally emit `turn_status` when a helper ends, so a long HYBRID turn shows its cost growing. Keep the final value as it is.

## Acceptance criteria

- AC-1: a test runs a HYBRID turn with fake costed calls (planner, two helpers, synthesis). Every `turn_status` after the first costed call carries a `turn_cost_usd` greater than 0 that equals the sum recorded so far. Fails if any mid-turn emission carries 0 after a cost was recorded.
- AC-2: the final `turn_status` equals the sum of the trace's recorded costs, as today.
