# FRE-1638: Telemetry: cache_read_tokens logs twice the real cache read on Anthropic calls

`model_call_completed.cache_read_tokens` on Anthropic calls is exactly 2x the cache read that the cost implies.

- `anthropic/claude-sonnet-5-5`: call 1 wrote 15,972 cache tokens. Call 2 logged `input_tokens` 23,041, `cache_read_tokens` 31,944, output 507, `cost_usd` 0.020805. The cost matches a cache read of 15,972: 7,069 × $2 + 15,972 × $0.10 + 507 × $10 per MTok = $0.020805. The logged 31,944 is 2 × 15,972, and it is larger than `input_tokens`.
- `anthropic/claude-sonnet-5`: a cache write of 16,040, then `cache_read_tokens` 32,080 on the next call. So the defect predates Sonnet 5.5.
- `api_costs` is correct (litellm computes the cost from its own usage). The `gpt-6.1-sol` calls show plausible values (for example 59,312 cached of 71,479 input).

## Probable cause (to confirm)

The extractor may add two fields that carry the same number, for example Anthropic's `cache_read_input_tokens` and litellm's `prompt_tokens_details.cached_tokens`. Find the code that fills `cache_read_tokens` for `model_call_completed`.

## Acceptance criteria

- AC-1: a test with a recorded Anthropic usage object (cache read N) gives `cache_read_tokens == N`. Fails if it gives 2N.
- AC-2: the same test for an OpenAI usage object (Chat Completions and the Responses route) keeps today's correct value.
