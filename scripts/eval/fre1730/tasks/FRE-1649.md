# FRE-1649: The gap redispatch can add workers beyond the per-turn expansion budget: bound it by the same budget

## The defect

An earlier change caps the number of workers in a plan by the per-turn expansion budget. The gap-triggered redispatch runs after the plan. It can add one replacement per task beyond the capped plan. With a budget of 1 and a one-task plan, `sub_agent_count` can reach 2. In the worst case it doubles the budget.

The budget is a load-shed signal. A doubled fan-out defeats it at the moment of highest load, which is the one moment it exists for.

## Scope

Bound the redispatch by the same per-turn budget that bounds the plan. The total number of workers started in one turn (plan plus redispatch) must not exceed the budget. Carry the budget from the gateway output to the redispatch path. Do not change the redispatch trigger rule. See `orchestrator/expansion_controller.py`.

## Acceptance criteria

- AC-1: the total is bounded. A test with budget 1, a one-task plan and a gap that triggers a redispatch ends with `sub_agent_count` 1 and a logged skipped redispatch. Fails if the count reaches 2.
- AC-2: the seeded negative. The same test with the bound removed ends with `sub_agent_count` 2. Fails if the test passes without the bound.
- AC-3: a calm turn is unchanged. With budget 3 and a three-task plan with one gap, the redispatch still runs when the total stays at or below 3. Fails if the redispatch is blocked below the budget.
