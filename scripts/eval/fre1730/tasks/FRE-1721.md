# FRE-1721: Gating watcher never triggers master when GitHub leaves a check at IN_PROGRESS with a conclusion set

A ready PR went green, and the gating watcher logged no `gating_decision` and no `gating_skip` for it. It never sent `/master <pr>`.

`gh pr view <pr> --json statusCheckRollup` shows the check `Detect changed paths` with `status: IN_PROGRESS`, `conclusion: SUCCESS` and a `completedAt` time. Every other check is COMPLETED.

In `scripts/dispatch/gating_watcher.py`, in `_check_state`, a CheckRun whose `status` is not `COMPLETED` returns `pending`, and the code never reads the conclusion. So `ci_status` stays `pending`, and `classify_pr` never returns the master-ready candidate.

The same path-filter check completed normally on other PRs. So the GitHub state appears only sometimes.

## Fix

In `_check_state`, treat a CheckRun as complete if it has a non-empty `conclusion`, even when `status` is not COMPLETED. GitHub sets a conclusion only when a run ends. Keep every other rule.

## Acceptance criteria

- AC-1: a unit test with a CheckRun of `status: IN_PROGRESS, conclusion: SUCCESS` gives `pass`. With `conclusion: FAILURE` it gives `fail`. Both tests fail before the fix.
- AC-2: a CheckRun with `status: IN_PROGRESS` and no conclusion still gives `pending`.
- AC-3: the existing `tests/scripts/test_gating_watcher.py` tests pass.
